# Live recording architecture

run_pipeline.py confirms the three component labels and supervises one recording. pipeline/runtime.py runs independent API and serial workers. Each worker writes its raw CSV and submits timestamped observations to a shared bounded window buffer. The controller snapshots each eligible window and computes features outside the buffer lock. Collector errors are reported and retried. Storage failures terminate the recording. Ctrl+C signals both workers, waits for their cleanup and drains complete windows through the stop time.

The API collector uses the endpoint pair and digest authentication workflow from the original API logger, with Requests digest handling, finite timeouts and host receipt timestamps. The serial collector reuses print_logger.find_port and adapts its six/seven-field parsing, bulk serial reads, conversion factors and native clock wrap handling. An explicit connection/segment identifier replaces the earlier fabricated reset interval. The board supplies the measurement times. Malformed lines and board messages remain in raw storage.

Timestamp normalization anchors each clock epoch to host receipt UTC and keeps its offset fixed within that epoch. A device prediction more than clock_jump_tolerance_s (default 0.5 seconds) ahead of its host anchor starts a new epoch. The preceding ambiguous segment is excluded from pending feature buffers, with exclusions counted. Native packet text remains in raw storage. Already finalized rows are never rewritten. Detected resets and reconnects start new segments. Missing sequence indices or an acquisition interval above sensor_gap_s (default 0.25 seconds) start a new feature segment without compressing device elapsed time. Out-of-order packets remain raw and are excluded from feature buffers.

Within each serial batch, native acquisition spacing is reconstructed backwards from the newest tick. Host receipt remains a separate field. Fixed clock offsets avoid silently compressing gaps or changing prior timestamp interpretations. Oscillator drift and unknown transport latency remain synchronization uncertainty. This implementation does not claim measured API-to-device alignment or apply drift correction. A forward discontinuity can indicate stale buffered packets or a clock anomaly; its cause requires hardware evidence. The receipt-minus-mapped residual is diagnostic and is not a bound on absolute timing error.

The scheduler emits matching half-open UTC intervals for both streams, including empty intervals. It defaults to 10 seconds with a 2-second stride and 0.5-second allowance. It never reopens a finalized row. Late observations remain raw. Capacity evictions are counted in diagnostics. Feature files are append-only and contain the same confirmed labels. A hard process or disk failure can interrupt a pair of CSV writes; verify matching IDs before training. A subsequent invocation always allocates a fresh directory.

Feature extraction adapts the original temperature/position field selection, native timestamp differences and interpolated Hann-window FFT. It computes three axis spectra independently. Duration-weighted signed filament velocity preserves retractions. The encoder also supplies movement duration as a percentage of the window and the longest continuous observed period without movement. Reported temperature and filament fields may include held readings. Each source produces its other supported features independently. Raw preservation, UTC mapping, and window selection are reusable by other consumers.

Thermocouple slope permits acquisition-gap boundaries that preserve the device-to-UTC mapping, with a configurable maximum valid-observation gap of one second. It requires at least five valid observations spanning eight seconds. Reset, reconnect, and ambiguous remapping boundaries prevent a cross-boundary slope. Temperature mean and standard deviation keep their existing calculation rules.
